# best-practices tools are not in the CI gate

## Symptom

A best-practices edit goes green in `bin/check.sh` and CI while `INDEX.md` or a reference file's Contents block is stale, or while `lint.sh` would report an error.

## What fails

Nothing in `bin/check.sh` [^s1] or `.github/workflows/ci.yml` [^s2] invokes `render-index.sh` or `lint.sh`. The gate runs only the repo-level `render-index.py` and `lint-skills.py`, which do not touch best-practices' outputs. Because `render-index.sh` writes `INDEX.md` at the plugin root [^s3], a rule added without rerunning it leaves that index stale.

Since 0.6.3, `render-index.sh` also writes a generated Contents block between `<!-- toc: generated by tools/render-index.sh -->` and `<!-- /toc -->` into every `references/*.md` over 100 lines [^s3]. A rule added without rerunning it leaves that file's Contents stale too.

## What works

Run both tools by hand after any edit under `modules/best-practices/`, and commit their output with the change. `render-index.sh` is idempotent, so a rerun on an up-to-date tree produces no diff. `lint.sh` exits 1 on any error [^s4].

## Why

The gate was built around the skill-level lints, so the best-practices-specific generators were never wired in. Nothing enforces their output, so drift is silent until someone reads the file.
