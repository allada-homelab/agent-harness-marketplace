# Authoring a module

## Layout

```
modules/<name>/
  .claude-plugin/plugin.json   # Claude: {name, version, description, author, license} — name == directory
  plugin.json                  # Agent Plugins v1 (agent-plugins.org): GENERATED by bin/render-plugin-manifests.py — Cursor/Codex/Copilot/Kiro/VS Code read it
  package.json                 # every module: {"name": "@allada-homelab/<name>", "version", "pi": {…},
                               #   "dsh": {"bundle": {"patch": "./cordis.patch.yml"}}} — content modules too,
                               #   or dsh installs the package as a plain dependency and ignores the patch
  cordis.patch.yml             # dsh loader rows; empty for a content module — the skills bridge is foundation
  mcp.json                     # optional: MCP servers, Agent Plugins v1 shape (see below)
  .mcp.json                    # the Claude spelling of mcp.json: GENERATED by bin/render-plugin-manifests.py
  skills/<skill>/SKILL.md      # THE shared content — commands are skills
  agents/<agent>.md            # optional subagents; see agent-contract/README.md
  workflows/<n>.workflow.js    # optional dynamic workflow; see workflow-contract/README.md
  extensions/<n>.ts            # pi adapter (optional; event-only, no registerTool)
  hooks/hooks.json             # Claude-shaped hooks; runs on pi/dsh through the hook runners
  lib/index.js                 # dsh adapter (optional)
  test/  README.md
```

A module with a `.claude-plugin/plugin.json` must have an entry in
`.claude-plugin/marketplace.json` with the same version. Bump all three when the
module changes; `bin/check.sh` asserts they agree.

## The portable `SKILL.md` contract

Enforced by `bin/lint-skills.py` (run through `bin/check.sh`).

- **Required**: `name` (== the directory name; Claude requires it, pi and dsh
  tolerate) and `description`. One tight paragraph: pi sends every loaded
  skill's name and description on every API request of the agentic loop, so a
  description must earn its line.
- **Allowed**: `argument-hint`, `user-invocable`, `disable-model-invocation`,
  `license`, `compatibility`, `metadata`, `harness: [claude|pi|dsh]`, `tags: […]`.
  `harness` and `tags` are this marketplace's selection vocabulary; every harness
  ignores them, so they are safe to publish.
- **Selection guidance lives in `description`.** dsh parses `whenToUse` and ships
  it over the API, but its skill catalog emits name and description only and the
  UI never renders it. Nothing may live there that the description lacks.
- **Directory form only**: `skills/<name>/SKILL.md`, never `skills/<name>.md`.
  dsh accepts the flat form and then hands the skill the *root* as its resource
  base, so `./scripts/x.py` resolves into the directory shared with every sibling.
- **A command** is `user-invocable: true` plus `argument-hint` (add
  `disable-model-invocation: true` when the model must never trigger it). It is
  `/name` on Claude, `/skill:name` on pi (`/name` through the pi harness's
  skill-commands foundation extension) and `/name` on dsh through the
  harness's skills bridge.
- **Substitutions**: `$ARGUMENTS` and `$N` only. Claude and pi expand them
  natively; dsh expands them only through the harness's skills bridge, so write
  the body so it still reads correctly with the token unexpanded and the user's
  text following as prose ("Research target: $ARGUMENTS").
- **Forbidden** in a portable skill: `hooks:`, `effort:`, any `context:` other
  than `fork`, and — outside a forked skill — `agent:`, `model:` and
  `allowed-tools:` (dsh drops it silently, and a tool
  restriction that vanishes is worse than none), plus `${CLAUDE_*}` placeholders,
  absolute or `~/` paths, and `` !`cmd` `` injection. A skill that needs one of
  these is Claude-only: scope it with `harness: [claude]` and the lint allows the
  Claude keys. Put harness-specific behavior in a sibling skill or module rather
  than in the shared one.
- **Forked skills** are the one exception. `context: fork` is portable: Claude
  runs the skill in a forked context and the pi and dsh bridges dispatch it as an
  isolated agent of type `<module>:<skill>` — body as the persona, `allowed-tools`
  tokens as the tool set, `model` as the alias. With it, `allowed-tools`, `model`
  and `agent` are allowed in an unscoped skill (`agent` only reaches Claude, so
  the lint warns unless it names a built-in — `Explore`, `Plan`,
  `general-purpose` — or a `<module>:<agent>` type), and `$ARGUMENTS` in the body
  is left verbatim. Read
  [`agent-contract/README.md`](../agent-contract/README.md) before writing one.
- **Assets** are referenced skill-relative (`./scripts/x.py`,
  `./references/y.md`) and must exist; the lint checks.

## Hooks

Ship one `hooks/hooks.json` in Claude's shape with `"type": "command"` handlers
and `${CLAUDE_PLUGIN_ROOT}` paths. Claude reads it natively; the pi and dsh
harnesses' hook runners map it onto their harness's seams. Read
[`hook-contract/README.md`](../hook-contract/README.md) for the exact stdin and
stdout contract and the two known fidelity gaps: `Stop` cannot block on pi (a
block becomes a follow-up user message) and `PreToolUse` cannot rewrite on dsh
(a rewrite becomes a deny whose reason carries the intended input). Turn-end
work should therefore run *after* the turn in the background on every harness.

## MCP servers

A module declares its MCP servers **once**, in `mcp.json` at the module root —
the [Agent Plugins v1](https://agent-plugins.org/specification) shape:

```json
{
  "$schema": "https://agent-plugins.org/schemas/1.0.0/mcp.schema.json",
  "mcpServers": {
    "docs": { "type": "stdio", "command": "npx", "args": ["-y", "@example/docs-mcp"],
              "env": { "DOCS_API_KEY": "${DOCS_API_KEY}" } },
    "search": { "type": "streamable-http", "url": "https://mcp.example.com/search",
                "headers": { "Authorization": "Bearer ${SEARCH_TOKEN}" } }
  }
}
```

Claude Code reads the *other* spelling — `.mcp.json`, the same servers under
`mcpServers` with no `$schema` — so that file is **generated** beside it by
`bin/render-plugin-manifests.py --write`; never hand-edit it, and never ship one
without an `mcp.json` to generate it from. pi and dsh consume `mcp.json` through
the harness layer's MCP registry.

`bin/check.sh` validates the source: the top-level shape is closed, a server name
is `[A-Za-z0-9_-]{1,32}`, a `stdio` `command` is one executable token (put the
rest in `args` — it is never run through a shell), a `streamable-http`/`sse` `url`
is HTTPS and not loopback, and a credential-shaped `env`/`headers` key must carry
a `${VAR}` reference rather than a literal. **Never commit a token.**

## Workflows

A module ships a dynamic workflow as `workflows/<name>.workflow.js` in Claude's
shape: a pure-literal `export const meta = {name, description, phases?}` plus a
body built from `agent()`, `parallel()`, `pipeline()`, `phase()`, `log()` and
`args`. Claude runs it with its Workflow tool; pi and dsh run the same file
through the harness layer's `run_workflow` tool as `<module>:<name>` (the
filename, not `meta.name`). Read
[`workflow-contract/README.md`](../workflow-contract/README.md) for the host
surface, the fidelity table (`effort`, `isolation`, `background` and
`resumeFromRunId` are ignored off Claude; a failed child is `null`) and the
bridge caps. `bin/lint-workflows.py` enforces the `meta` literal.

## Checking

```
bin/check.sh                              # everything; what CI runs
bin/lint-skills.py                        # just the skill contract
bin/lint-workflows.py                     # just the workflow contract
bin/render-index.py --write
bin/render-plugin-manifests.py --write    # plugin.json and .mcp.json
```
