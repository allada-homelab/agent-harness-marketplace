### Notable findings

- **DOCKER-032**: `--resource` keys are `memory`/`cpu-shares`/`cpu-period`/`cpu-quota`/`cpuset-*` (one per flag; bake uses `resources`); shipped buildx v0.35.0 — Requires `buildx>=0.35, buildkit>=0.31`.
- **COMPOSE-014**: nginx:alpine now ships curl (8.22.0) and busybox wget with `--spider` — the "does not ship wget or curl" premise is outdated.
- **COMPOSE-019**: remote `oci://` for `include:` shipped in Compose 2.30.0, not 2.34.0.
- **UV-003**: link-mode default is now `clone` (copy-on-write) on macOS/Linux since uv 0.10.5, `hardlink` only on Windows; **UV-010 is missing a Requires tag** — it depends on `UV_NO_INSTALL_PROJECT`/`UV_NO_INSTALL_WORKSPACE` (uv 0.11.20, <12 months) and needs `uv>=0.11.20`.
- **UVP-027**: uv publish does NOT generate PEP 740 attestations — they must be created separately; it only uploads pre-created ones. **UVP-030**: setup-uv latest is v10.3.3, not v8.2.0. **UVP-060**: astral-sh/migrate-to-uv is 404 — the tool moved to osprey-oss/migrate-to-uv. **UVP-062**: pip pylock support is experimental and landed in pip 26.1, not 25.1.
- **PY-083**: the import path is wrong — the class is `concurrent.futures.InterpreterPoolExecutor`, not `concurrent.interpreters.…`. **PY-089**: `uv_build>=0.11,<0.12` is unresolvable (current uv_build 0.13.6). **PY-075**: attestations are on by default with Trusted Publishing and need NO `attestations: write` permission. **PY-060**: the setuptools deprecation deadline is 2027-02-18 (not Feb 2026); PyPI rejects only when License and License-Expression are both present. **PY-034**: pytest-asyncio 1.4.1 runs fixture+test in the SAME task — the contextvars rationale is stale. **PY-045**: `create_task` COPIES the current context — "drops contextvars" is wrong. **PY-011**: pyrefly conformance is 87.8% (not >90%), README says 15× (not 10–50×). **PY-093**: the quoted example mixes modes.
- **GO-009**: errgroup now has `SetLimit`/`TryGo` — "no semaphore" is stale. **GO-014**: math/rand is auto-seeded since Go 1.20 — the identical-ID failure mode is gone (predictability is the real issue). **GO-021**: `PathValue` in a go-1.21 module compiles fine and silently 404s — the trap is WORSE than the rule says (no compile-time signal).
- **CC-059**: allowManagedHooksOnly wording too broad (force-enabled plugin hooks and Agent SDK hooks still run). **PROMPT-009**: per-message effort is beta and needs the `mid-conversation-output-config-2026-07-01` header (400 without it).
- **REPO-004**: stock gitleaks hook entry is now `gitleaks git --pre-commit --redact --staged --verbose` (rule omits two flags); the "0 commits scanned on clean checkout" claim verified live with v8.30.1.
- **OBS-005**: the OTEL_SEMCONV_STABILITY_OPT_IN quote is misattributed — it lives in the semconv http-migration guide, not the spec env-var page. **FAPI-095**: floor should be `fastapi>=0.121.1` (0.121.1 fixed `scope="function"` for parameterless deps).
- **Requires-tag audit**: existing tags are correct (CC-080/081, GRPC-022/024, REPO-011, SQLITE-007); flagged: DOCKER-032 (floor too low), DOCKER-031 missing `dockerfile>=1.20`, UV-010 missing `uv>=0.11.20`, PY-077 missing `(preview: audit-command)`, FAPI-095 floor imprecise, GRPC-024's `grpc-go>=1.12` arguably stale (every supported install meets it).

## Methodology

- **Scope**: every rule in the 9 rule-bearing best-practices skills (claude-code, containers, databases, fastapi, go, grpc, python, repo, uv) — **498 rules**, including the rules added since the 2026-10-25 run (the verified candidates became real rules in best-practices 0.8.0; corrections landed in 0.7.1; `Requires.` tags in 0.7.0). `meta-best-practices` (the rule-format spec) and `containers-audit` (an audit workflow) were excluded.
- **How each rule was checked**: a per-domain validator read the skill's SKILL.md, its references/ and the INDEX entry, then verified the rule's claim against the tool/language/framework's **current official documentation**, and — where the claim is version-gated — **ran the real tool** (`uv`, `python3`, `go`, `sqlite3`, `psql`, `docker`, `pre-commit`, `gh actions-lock`) and quoted its output. Verification used web search, page fetches, library-doc lookups and direct fetches (searxng, context7, curl) where the MCP tools were unavailable.
- **Version floors**: before writing a verdict or candidate, the validator read `meta-best-practices`' "Version floors (`Requires.`)" section and followed its policy. Every UPDATE row and every candidate carries a `Requires` column value ("none" when no floor applies).
- **Preview/stable status**: no feature was labeled preview/experimental/stable from a doc note alone — the real command's warning (or its absence) is quoted. (The 2026-10-25 UVP-063 lesson held: docs still call `add-bounds` preview while uv 0.13.6 writes exact bounds with no warning.)
- **No duplicate candidates**: a candidate that merely repeats an UPDATE row was folded into that UPDATE row instead; the fold is called out in the validator notes.
- **Verdict scale**: VALID · UPDATE · SUPERSEDED · REMOVE · UNVERIFIED (what would confirm it is named). Every verdict carries a citation; an uncited verdict is UNVERIFIED by definition. Secondary claims a validator could not reach are flagged in the evidence line.
- **Report-only**: no rule, reference file, index or manifest was edited. The verdicts and candidates here are proposals for a separate reviewed task that applies them.
- **Candidate IDs**: next free slot per prefix (INDEX-derived), so a later application can add them without renumbering.
