### Notable findings

- **UVP-071 should be removed**: `[tool.uv.build-backend] import-names` is not a real key (verified: silently ignored; the correct key is `module-name`, and PEP 794 `import-names` is a `[project]` key).
- **SEC-012's rationale is factually wrong** (verified empirically): an excluded `.env` makes `COPY .env` fail — an explicit COPY does not bypass `.dockerignore`; the real risk is an un-ignored, committed `.env`.
- **FastAPI 0.142.0 (2026-09-29) added native OpenTelemetry** (`FASTAPI_OTEL_AUTO_CONFIGURE`) — OBS-003 and OBS-005 should point at the native path rather than the hand-rolled FastAPIInstrumentor recipe; new candidate FAPI-093 captures it.
- **CC-023's mechanism moved**: compaction steering is now a SessionStart `compact` re-injection and `/compact` with instructions, not a bare CLAUDE.md note.
- **CC-076's rationale is weakened**: tool search makes MCP context cost minimal, so no current doc states a CLI is more context-efficient than an MCP server.
- **GO-005 and GO-014**: `errors.AsType[E]` is now the preferred type-match form (Go 1.26), and `crypto/rand.Read` is guaranteed not to fail since Go 1.24 (`crypto/rand.Text()` added) — both rules' wording is stale.
- **GRPC-016's keepalive example** (Time 30s + PermitWithoutStream) conflicts with grpc.io keepalive guidance (~1 minute, avoid pings without calls).
- **FAPI-006's "never by header"** is now too absolute: AIP-185 endorses interface-based versioning via `X-Goog-Api-Version` or `$apiVersion`.
- **Version stamps drift**: Python 3.15.1 / uv 0.13.5 / SQLite 3.54.1 / PostgreSQL 18.6 / Go 1.27.3 / SQLAlchemy 2.0.55 / Alembic 1.20.1 / FastAPI 0.162.0 are current; several rules cite one release behind, and UVP-073's default-Python fact (3.15 since uv 0.13.0) is stale.
- **Numbering gaps confirmed**: DOCKER-008 and COMPOSE-008/022/024/025 carry no rule (retired slots); the validated total (461) matches the INDEX count exactly, and candidate IDs use the next free slot after each prefix's real max (e.g. DOCKER-034, COMPOSE-030, UVP-076).

## Methodology

- **Scope**: every rule in the 9 rule-bearing best-practices skills (claude-code-best-practices, containers-best-practices, databases-best-practices, fastapi-best-practices, go-best-practices, grpc-best-practices, python-best-practices, repo-best-practices, uv-best-practices). `meta-best-practices` (the rule-format spec) and `containers-audit` (an audit workflow, not a rule family) were excluded.
- **How each rule was checked**: a per-domain validator read the skill's SKILL.md plus its reference files and the INDEX entry, then verified the rule's claim against the tool/language/framework's **current official documentation** (primary sources: docs sites, PEPs, specifications, official guides; current version noted where relevant). Verification used web search, page fetches and library-doc lookups (searxng, direct fetches, context7).
- **Verdict scale**: VALID (still correct as written) · UPDATE (correct in substance, wording/detail outdated) · SUPERSEDED (a newer practice replaces it) · REMOVE (no longer correct or useful) · UNVERIFIED (no source found; what would confirm it is named).
- **Evidence rule**: every verdict carries a citation; an uncited verdict is UNVERIFIED by definition. Where a validator could not reach a secondary claim (rate-limited search engines, a GitHub-issue reference), the evidence line flags it explicitly rather than asserting it.
- **Report-only**: no rule, reference file, index or manifest was edited. The verdicts and candidates here are proposals for a separate reviewed task that applies them (per the meta-best-practices authoring procedure).
- **Candidate IDs**: next free slot per prefix, so a later application can add them without renumbering existing rules.
- **Idempotency**: this report is the product of the 2026-10-25 run; the weekly task guards against duplicate runs by checking the dated branch on origin first.
